Задание 6. Охота на вредоносный процесс

1. Что обнаружено
В ходе анализа системы были выявлены два подозрительных процесса, запущенных от имени обычного пользователя riki:
- PID 2654: процесс с именем kworker, запущенный с аргументом 3000.
- PID 2656: процесс python3, слушающий сетевой порт.

2. По каким признакам найдено (4 признака маскировки)

Признак 1: Подозрительное имя
Команда: ps -eo pid,user,cmd | grep kworker
Вывод показал множество процессов [kworker/...] от имени root в квадратных скобках (это настоящие потоки ядра). Среди них выделялся процесс:
``text 2654 riki /tmp/kworker 3000 Он не заключен в квадратные скобки и запущен от обычного пользователя, что нехарактерно для системных процессов ядра. **Признак 2: Запуск из временного каталога** Тот же вывод ps показал, что исполняемый файл находится в /tmp (/tmp/kworker 3000). Системные процессы не запускаются из временных директорий, доступных на запись любому пользовaтелю. **Признак 3: Удалённый с диска файл** Команда: sudo ls -l /proc/*/exe 2>/dev/null | grep -E '/tmp|/dev/shm|deleted' Вывод:lrwxrwxrwx 1 riki riki 0 окт  9 23:44 /proc/2654/exe -> /tmp/kworker (deleted) Символическая ссылка /proc/2654/exe указывает на файл с пометкой (deleted). Это означает, что файл был удалён с диска после запуска процесса, чтобы скрыть следы, но сам процесс продолжает работать в оперативной памяти. **Признак 4: Открытый сетевой порт** Команды: sudo ss -tulpn | grep 8080 и sudo lsof -i :8080 Вывод:tcp LISTEN 0 5 0.0.0.0:8080 0.0.0.0:* users:(("python3",pid=2656,fd=3)) COMMAND  PID USER   FD   TYPE DEVICE SIZE/OFF NODE NAME python3 2656 riki    3u  IPv4  26697      0t0  TCP *:http-alt (LISTEN) Обнаружен процесс python3 (PID 2656), который открыл порт 8080 для прослушивания всех интерфейсов (0.0.0.0), имитируя бэкдор или утечку данных. **3. Почему это подозрительно** Настоящие kworker — это потоки ядра, они всегда принадлежат root и отображаются в ps в квадратных скобках [ ]. Каталог /tmp очищается при перезагрузке и доступен всем, легитимные демоны там не хранятся. Пометка (deleted) в /proc/PID/exe — классический индикатор компрометации (IoC), означающий, что злоумышленник попытался замести следы, удалив бинарный файл. Неожиданно открытый порт на нестандартном сервисе (http-alt) без ведома администратора указывает на несанкционированную сетевую активность. **4. Как устранено** Для ликвидации угрозы были принудительно завершены оба процесса по их PID:kill 2654 kill 2656 **Проверка:** Повторный вызов ps -eo pid,user,cmd | grep kworker | grep -v grep и sudo ss -tulpn | grep 8080 не вернул никаких результатов. Процессы отсутствуют, порт закрыт, угроза снята. **5. Вывод** При поиске вредоносного процесса **нельзя доверять его имени** (колонка CMD в ps), так как его можно подделать (например, назвать скрипт kworker или systemd). Доверять нужно содержимому **/proc/PID/exe**, так как это прямая символическая ссылка, которую поддерживает само ядро Linux. Она указывает на реальный исполняемый файл на диске. Если файл был удалён, ядро честно добавляет пометку (deleted)`, что является неопровержимым доказательством аномалии, которое злоумышленник не может подделать из пользовательского пространства.
